How it would run in production

The same steps and checks as this prototype. Each piece is swapped for its production version behind the interface it already has.

People approve in the web app, and a worker does the rest

Hosted in the UK or EU, behind company sign-in. Nothing reaches a doctor until a person has approved it.

What changes from this prototype

PartThis prototypeProduction
Runs onOne laptop, or Vercel for the demoAn always-on server or container in the UK or EU
DatabaseA SQLite filePostgres, backed up every day
Long jobsA background thread in the web appA worker that takes jobs from a queue
DraftingThe local model (Ollama)A hosted model under a data agreement, or our own GPU server
Email checksMade-up fixturesPaid verification and finder services, behind the same interface
SendingRedirected to your inbox through ResendMedicPaths' own domain, with SPF, DKIM and DMARC
PeopleA typed nameCompany sign-in, with reviewer and admin roles
AlertsA fileA webhook to n8n, then WhatsApp, Slack or Teams
Watching itThe audit logThe audit log, plus error tracking, uptime checks and a daily summary

The steps, rules and checks stay the same. The model, the email checks, the sender and the alerts each sit behind one small interface, so each can be swapped without touching the rest.
